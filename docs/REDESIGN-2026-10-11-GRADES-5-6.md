October 11, 2026. Reviewed draft on the branch `claude/circ-hq-grades-5-6-redesign-9b3tmr`, started from main at commit `ef2c4888837d41a8e65e8346c144b8a9d4ffed9b` (checked against the remote on October 11; it was still the latest main). ## Outcome in one paragraph

The student side now opens on this year's next meeting with one button per grade, every lesson reads in a child's order (goal, done-when check, grade target, materials, safety, timed steps, turn-in, next challenge, another way, a stuck-then-try list, links), and a search box with grade and playbook filters replaces the two jargon dropdowns. Every one of the 74 unique lessons has its own small tagged PDF and an editable Word response sheet, listed on a new handouts page with filters by grade, playbook and format, and linked from the lesson, the teacher's class card and the Playbooks page. The teacher's class card shows materials, safety and the pacing bar before Start, and the projected Student directions view gained a one-click way back to the teacher controls. Playbooks A and B, lesson IDs, the 35-minute structure, manual step control, both clocks, the new-class reset, recovery, backup and import, every storage key and every route are unchanged. All 16 public release gates still pass; new public files were added to the gates explicitly, none were loosened.

## Design rationale

1. **The next action is the first thing on the screen.** A ten-year-old without a link saw a playbook dropdown, a meeting-number dropdown of bare numbers and two grade buttons. The data already knew which playbook is this year and which meeting is next, so the landing now says "What are we doing today?", names the lesson and its goal, and offers "Grade 5" and "Grade 6" as real links. A small form handles "the teacher wrote a different number on the board". The cue comes only from the static `nextMeeting` and `done` flags, never from the date, which keeps the "mark a class by its record, never by the date" rule.
2. **Lesson pages read in the order a child needs them.** The done-when check moved from the bottom to a yellow card under the goal, the student's own grade target sits right under it (with the other grade's target in a quieter line so the difference is clear), safety comes before the steps, a time bar shows the shape of the lesson before anyone reads a word, and a "Stuck? Try this order" card gives the help the data never had. Ten lesson fallbacks were written in the teacher's voice ("This lesson is already device free."); the student page shows "No computer is needed. The steps work as written." for those without changing the data. Teacher planning notes that leaked into student copy (a unit season that continued "Teacher places the four visits...", the done note "Use it only for a class that missed it") are trimmed on the student side only.
3. **One look across the student pages.** The student page used to load the old light-blue base styles while the teacher page used the navy and cream theme and Fredoka and Nunito Sans. The student pages now share one token set (navy ink, CIRC blue, cream canvas, yellow for the done-when check, green for finished states, amber for safety) and the same two typefaces, with the fonts self-hosted so a student device makes no third-party request at all. Nothing on the student pages is animated; reduced-motion and print rules are in place; every control is at least 44 px tall; no emoji, gradients or decorative images.
4. **Resources are findable and small.** Instead of a 158-page guide or a 731-page deck, each lesson is one PDF of two or three pages with real text, headings as bookmarks, letter size, page numbers and a fixed friendly filename, plus a Word response sheet for Teams assignments where students type. Both are generated from the live lesson data by scripts, so they can never drift from the on-screen lesson the way the September 30 PDFs did. The four existing PDFs stay unchanged and are labeled with their dates and their known drift.
5. **The teacher path got shorter without touching the runner.** The class card now shows setup, materials, safety and a pacing bar, and links the lesson's PDF, so a teacher sees everything a lesson needs before pressing Start. While projecting Student directions, "Teacher controls" returns straight to the runner (Next Step then Student directions again is now 3 clicks per step; it was 4 through Today). The six-item teacher nav no longer clips on a 390 px phone.

## How to preview

```powershell
npm ci
node scripts/dev-server.mjs
```

Then open `http://127.0.0.1:4273/student.html` (student side), `http://127.0.0.1:4273/resources.html` (handouts and guides) and `http://127.0.0.1:4273/` (teacher side). Deep links such as `student.html?playbook=a&meeting=10&grade=5` work as before.

```powershell
npm test
npm run verify
```

On a machine outside Eastern time set `TZ=America/New_York` first: 23 pre-existing tests in `tests/app-render.test.mjs` and `tests/teacher-home.test.mjs` build their clocks from local time and fail under UTC on the untouched main branch too. That is a test-environment limitation, not a code change, and it was not altered here.

To rebuild the handouts after a lesson change:

```powershell
npm run build:response-sheets
npm run build:handouts
```

`build:handouts` needs a Chromium-based browser; set `CIRC_CHROME` to its path or `CIRC_CHROME_CHANNEL=chrome` or `msedge`. Rebuilt files are byte-identical on the same machine. On a different machine the embedded system fonts differ, so the script rewrites `scripts/handout-manifest.mjs` and the diff is reviewed like any other public change.

## Representative walkthroughs (simulated review, not a student test)

Student tasks, counted in taps on the new pages:

1. "Open today's lesson for my grade": tap Grade 5 on the landing. One tap. Before: choose a playbook, choose a meeting number from a list of bare numbers, then a grade button.
2. "The board says meeting 23": type 23, tap Open. Two interactions.

## Rollback plan

Main is untouched. To discard the work, close the draft pull request and delete the branch. If it is merged and later reverted, one `git revert` of the merge commit restores main exactly: there is no data migration, no storage key or schema change, and no change to the student link format, so nothing a teacher saved on a device is affected either way. Only `resources.html`, `student.css`, the fonts and the handouts would disappear from the site after a revert; every link that existed before the change keeps working.

## Assumptions and decisions made without asking

- The session's designated branch was used instead of creating `redesign/grades-5-6-review`; the review content is the same.
- Handouts are keyed by lesson, not by meeting, so a lesson used in both playbooks has one file; the handouts page shows every place it is used.
- PDFs use system fonts by default so the build needs no network and the files stay small; `CIRC_HANDOUT_WEB_FONTS=1` switches to the site's fonts at about twice the size.
- The student pages self-host the two typefaces (latin subsets under the SIL Open Font License, license file included) rather than call Google Fonts, so a child's device makes no third-party request. The teacher page and the arcade still load Google Fonts as before.
- The student-side token set deliberately differs a little from `theme.css` (darker link blue, warmer yellow) because the student pages needed higher contrast on cream; the teacher theme was not restyled.
- The Command Center file was read at Revision 20 (October 9, 2026) and again at Revision 21 (October 13, 2026) for the merge; nothing in it changed this work beyond the no-dash and no-fake-hype writing rules and the routine-publishing authorization, which this branch uses only to push a review branch and open a draft pull request.
